# Experiment: Apple-style feel (branch `experiment/apple-design`)

**Status:** experiment only. Lives in its own branch and folder
(`cio_build_apple-design`). Never pushed, never merged, never deployed.
`main` and https://cio-cpf.vercel.app are untouched.

**Question:** how much does the `apple-design` skill (WWDC "Designing Fluid
Interfaces" etc.) change how the demo feels?

## Constraints (from CLAUDE.md)

- **No new library.** Springs, gestures and materials are built with what the
  browser already has (CSS `linear()` easing, Pointer Events,
  `requestAnimationFrame`, `backdrop-filter`). The skill suggests Motion /
  Framer Motion; using it would need Nadim's OK, so a ~60-line spring
  (`src/lib/spring.js`) does the same job here.
- **No behaviour change.** Same screens, same rules, same texts, same data.
  Only *how it looks and moves*. All 167 tests must still pass.
- Reduced motion, reduced transparency and higher contrast all respected.

## Plan (skill section in brackets)

### 1. Motion foundation (§4, §14)
- `src/lib/spring.js`: a critically damped / under-damped spring (damping
  ratio + response, Apple's two parameters), with initial velocity, that can
  be re-targeted mid-flight from its current value and velocity. Plus
  `project()` (momentum projection) and `rubberband()`. Unit tests.
- In `index.css`, spring curves as CSS tokens made with `linear()`:
  `--spring-smooth` (damping 1.0, response 0.4) and `--spring-bouncy`
  (damping 0.8, response 0.35). Generated by the same spring maths.
- Press feedback instant on pointer-down (100 ms), release on the spring.

### 2. Segmented controls with a sliding "thumb" (§3, §7, §16 Familiarity)
- Role switch (Élève / Conseillère), the counselor's tool picker, the phone
  day picker: the selected background becomes one piece that **slides** to
  the new choice (like iOS segmented controls), animated with CSS
  transitions on `transform`, which re-target from the current value if you
  click again mid-flight.

### 3. Week navigation with direction (§7 spatial consistency, §8)
- « Semaine suivante » brings the new week in from the right; « précédente »
  from the left; « Revenir à cette semaine » from the correct side. Same
  path back and forth.
- Phone: **swipe the day** (1:1 with the finger, rubber-band at Monday and
  Friday, velocity projection decides if the swipe commits, spring settles
  with the finger's velocity) (§2, §5, §6, §9, §10 hysteresis 10 px).

### 4. Dialogs become materials, phone dialogs become sheets (§7, §12, §2, §5)
- Computer: dialogs "materialize" (scale + blur + fade together) and the
  page behind dims; exit mirrors entry.
- Phone (< 640 px): every dialog is a **bottom sheet** with a grabber. Drag
  it down to dismiss: follows the finger 1:1, rubber-bands upward, uses the
  release velocity and projection to decide close vs. snap back.
- Settings sheet slides on a spring.

### 5. Translucent chrome (§12)
- Header: real glass (blur + saturate), content scrolls under it; the hard
  shadow becomes a soft scroll-edge fade. CPF colour band kept.
- Reduced transparency → solid header; higher contrast → solid + border.

### 6. Typography (§15)
- Size-specific tracking: the week title and the app name tighter
  (-0.02em), small labels a hair looser; tabular numbers on times;
  `text-wrap: balance` on titles.

### 7. Feedback that lands on the cause (§13, §16 feedback)
- Counselor: a cell that changes state (Fermé → Disponible → …) does a small
  spring "settle" so the change is noticed where the click happened.
- Student: the booking confirmation icon pops in on a bouncy spring
  (a completion moment, so a little bounce is earned).
- Vibration (phones that support it) only on commit moments: booking
  confirmed, swipe snapping to a new day. Never on simple taps.

### 8. Accessibility check
- `prefers-reduced-motion`: no slides, no springs, short cross-fades.
- Keyboard focus rings unchanged; swipe is an extra, buttons still work.

## Review of this plan (done before coding)
- *Risk: swiping on the counselor grid fights with her clicks.* Swipe only
  starts after 10 px of mostly-horizontal movement, and only on phones
  (touch/pen pointers), so clicks and vertical scroll are unaffected.
- *Risk: sheets vs. tall dialogs* (« Prochains rendez-vous », EDT import are
  already full-screen on phones): they keep their full-screen layout; the
  drag-to-dismiss is only on the grabber + header, never inside scrolling
  content, so lists still scroll.
- *Risk: Radix controls the dialog's open/close.* Drag-dismiss just calls
  the same `onOpenChange(false)` path, so nothing about the logic changes.
- *Dropped:* sound effects (no causal sound in a school app, §13 utility),
  parallax/background motion (§14), custom font (Poppins is still an open
  question for Nadim; system/Geist kept).
